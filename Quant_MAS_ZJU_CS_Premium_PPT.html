MCP 风格内部协议（M13）

  • tool_to_mcp_spec() — BaseTool → MCPToolSpec（name / parameters / safety_tags）
  • registry_to_mcp_specs() — 批量导出工具 schema，供 Agent 与 UI 发现

  • 每个工具参数在 TOOL_PARAMETER_SPECS 中显式声明类型与必填项

ToolPolicy：Deny-by-default 白名单

  • 允许：data_summary, backtest, train_model, report, ml_backtest, pipeline, risk_check
  • 拒绝工具名模式：shell · exec · broker · order · live_trade
  • 拒绝参数模式：api_key · secret · password · token · .env 路径
  • 决策：ALLOW / DENY / REQUIRE_CONFIRMATION

调用闭环：调度器或 Agent 发起 MCPToolCall → Policy 鉴权 → 通过后 registry.get(tool_name).run(**arguments) → 结果封装为 MCPToolResult 并写入 audit.jsonl。拒绝则直接 DENY，不触达 Engine。

Part II · Engine Core

回测引擎 BacktestEngine：确定性仿真成交

17 / 31

无未来 leak 的严谨成交假设

  1. 因果序列设计：策略在 T 日收盘后计算出 target_weight。
  2. 成交价格机制：引擎强制模拟在 T+1 日开盘价 (Open Price) 进行撮合交易，避免使用收盘价造成的未来函数。
  3. 摩擦损耗模型：引入滑点模型 (SlippageModel) 惩罚成交价，应用佣金模型 (CommissionModel) 扣除手续费。
  4. 多标的复合缩放：初始现金按多标的均分，独立运行后，最终汇总权益曲线。

结构化产物与审计链路

  • equity_curve.csv：持久化记录全时序每日资产净值净变化。
  • trades.csv：详尽审计每笔开仓、平仓开销明细。
  • metrics.json：输出夏普比率、最大回撤、波动率等。

自动注册至全局实验存储器中，大语言模型仅能读取或优化其超参数，无法更改成交引擎的计算逻辑。

Part II · Machine Learning

LightGBM 预测模型：两种切分模式对比

18 / 31

模式 A：单次静态时序切分 (诊断用)

基于 TrainModelTool 触发，将全样本按时间硬切为 70% 训练集、15% 验证集、15% 测试集。

  • 静态测试结果：测试集 AUC 为 0.479 (接近随机)。
  • 学术诊断结论：静态时序切分在非平稳金融时序中完全失效，印证了必须引入滚动前瞻重训的迫切性。

模式 B：Walk-Forward 滚动重训 (主路径)

每个滚动时间窗口重新 fit 一个独立的 LightGBM 实例，全面启用 device=cuda 硬件加速。

  • 核心超参数设置：n_estimators=100, learning_rate=0.05, num_leaves=31。
  • 过拟合图景剖析：单窗内部训练集 AUC 逼近 0.997，但对应窗口的样本外 AUC 则骤降至 0.472，揭示了过拟合的严重程度。

基于置信度区间的双阈值状态机

模型不直接输出动作，而是通过策略层消费预计算的概率矩阵 pred_proba，确保运算的因果逻辑。

核心逻辑的系统互补特性

  • MaCross 策略：纯经验驱动，具有强解释性，作为系统的底线基准。
  • MLSignal 策略：由数据置信度驱动，在非线性模式发掘上更优，配合 Walk-forward 构成了系统的主结论实验路径。

注意：两者共用同一成交回测内核，确保了对比的绝对公平。

单窗算法内部循环流程 (run_walk_forward)

  1. 提取当前窗口的 train/val/test/oos 时间戳索引。
  2. 执行 fit LightGBM(train) 并对后续各时段进行预测。
  3. 计算并持久化各区间的 AUC、准确率，以便监控衰减。
  4. 在锁定的 OOS 样本外区间运行 MLSignalStrategy。
  5. 合并 19 段独立的 OOS 权益，产出全局最终业绩指标。

消融实验工程化推论

学术级结论：多模态文本信号注入后，性能未能跑赢基础量价基线。系统底层审计显示：核心矛盾在于覆盖率过于稀疏 (真实高价值新闻仅覆盖 146 / 6033 交易行)，导致模型倾向于学到噪声。这证实了 Walk-forward 回测对于发现多模态虚假增益的严谨价值。

Part II · Reinforcement Learning

强化学习模块：基于 GRPO 的组内策略优化 (M7)

22 / 31

去 Critic 架构的量化探索动机

传统 PPO 依赖 Critic 网络拟合状态价值函数 V(s)，在低信噪比的金融序列中，Critic 自身极易发散，导致多智能体不收敛。

  • 组内无监督评分：针对同一市场状态，并行采样由 G 个策略突变体组成的智能体组，免除 Critic 显存开销。
  • 相对优势判定：直接通过智能体组内收益的相对排名提取优势函数，天然过滤掉了大盘普涨/普跌的系统性高噪声。

严谨物理边界拦截规约

强化学习及 GRPO 的动作空间探索，其产出指标一律强制归入 simulation.* 或 training.* 命名空间中。

★ 严禁将强化学习仿真过程中的超高收益指标直接写入主成效表中，策略必须通过多阶段 OOS 回测判定桥才能进行最终汇报。

Part III · Conclusion

系统局限性与下一步展望

30 / 31

多模态文本局限性

目前外部高质量金融新闻流的实际覆盖率仅为 2.4%，导致模型对情感密集的异动行情缺乏捕捉能力。

未来改进：计划在下一阶段开展 EXP-TEXT-002 实验，引入 LoRA 轻量化微调的金融垂直领域大模型 FinBERT-ZJU，并成倍拉长数据回测时序窗口。

强化学习转化缺陷

多智能体种群自博弈在仿真环境 (Simulation) 中产生的极高奖励，经由样本外 OOS 回测验证后，依然存在较为显著的性能回撤衰减。

架构反思：真实市场的机制切换 (Regime Switching) 极其严酷，强化学习的动作奖励塑形仍需更强健的方差控制算子进行硬性约束。

下一阶段工作清单

  1. 推进学术论文撰写与更多 OOS 稳健性检验。
  2. 采用异构随机种子重跑 19 窗 Walk-forward 回测，以验证参数的统计显著性 (p-value)。
  3. 重构 WebUI，提供端到端由大语言模型自主触发、自主提交、自主监控的全自动量化科学实验工作流。

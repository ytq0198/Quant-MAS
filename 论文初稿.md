# Quant MAS: A Multi-Agent Quantitative Research Platform with Deterministic Engines, Memory, and Out-of-Sample Validation

# Quant MAS：一个结合确定性量化引擎、实验记忆与样本外验证的多智能体量化研究平台

## Abstract / 摘要

Quant MAS is a research-oriented quantitative intelligence platform that separates deterministic quantitative computation from language-agent orchestration. The system assigns data ingestion, feature engineering, model training, strategy generation, backtesting, walk-forward evaluation, risk checks, and reporting to a reproducible Quant Engine, while the Agent Layer is limited to planning, explanation, report generation, memory retrieval, and tool coordination. This design avoids allowing large language model agents to directly place live orders and instead requires every trading candidate to pass backtesting, risk control, audit logging, and human confirmation.

Quant MAS 是一个面向科研的量化智能体平台，其核心思想是将确定性量化计算与语言智能体编排明确分离。系统将数据获取、特征工程、模型训练、策略生成、回测、walk-forward 样本外评估、风控检查与报告生成交给可复现的 Quant Engine，而 Agent Layer 仅负责研究规划、解释、报告、记忆检索和工具编排。该设计避免让大语言模型智能体直接进行实盘下单，并要求所有交易候选都必须经过回测、风控、审计记录和人工确认。

The current implementation has completed a full research loop covering traditional moving-average strategies, LightGBM-based direction models, ML signal backtesting, walk-forward validation, population-based strategy candidates, and a preliminary reinforcement-learning candidate bridge. The primary paper baseline is a walk-forward out-of-sample evaluation with `oos.sharpe = 0.586` and `oos.total_return = 0.443` in experiment EXP-20260602-008. Additional ablation studies show that text signals reached `oos.sharpe = 0.563` under sparse coverage (EXP-TEXT-WF-001), `0.579` under full coverage with placeholder headlines (EXP-TEXT-WF-002), and `0.565` under real Finnhub news with 2.42% coverage (EXP-TEXT-WF-003), population-derived rule candidates reached approximately `1.036-1.039`, and an observation-aware RL candidate improved from an all-cash RL ablation (`0.0`) to `0.387`, although it remained below the ML baseline.

当前实现已经完成从传统均线策略、LightGBM 方向预测模型、机器学习信号回测、walk-forward 样本外验证、种群策略候选，到初步强化学习候选桥接的完整研究闭环。论文主基线采用 EXP-20260602-008 的 walk-forward 样本外评估，结果为 `oos.sharpe = 0.586`、`oos.total_return = 0.443`。其他消融实验显示：文本信号在稀疏覆盖下为 `oos.sharpe = 0.563`（EXP-TEXT-WF-001），全量覆盖占位文本下为 `0.579`（EXP-TEXT-WF-002），真实 Finnhub 新闻 2.42% 覆盖下为 `0.565`（EXP-TEXT-WF-003），种群生成的规则型候选约为 `1.036-1.039`，观测感知 RL 候选相较全现金 RL 消融结果 `0.0` 提升到 `0.387`，但仍低于 ML 主基线。

## 1. Introduction / 引言

Recent advances in large language models have made it possible to build research assistants that can plan experiments, summarize evidence, and orchestrate tools. However, financial trading systems require deterministic computation, strict auditability, and robust separation between research suggestions and executable orders. Directly allowing an LLM agent to trade would introduce unacceptable risks, including hallucinated decisions, non-reproducible reasoning, and insufficient risk control. Quant MAS is designed to explore how multi-agent systems can assist quantitative research without violating these safety boundaries.

近年来，大语言模型的发展使研究助手能够规划实验、总结证据并编排工具。然而，金融交易系统要求确定性计算、严格可审计性，以及研究建议与可执行订单之间的清晰隔离。若允许 LLM 智能体直接交易，将引入不可接受的风险，包括幻觉决策、不可复现推理和风控不足。Quant MAS 的设计目标是在不突破安全边界的前提下，探索多智能体系统如何辅助量化研究。

The central research question of this project is not whether an LLM can directly discover a profitable trading strategy, but whether an agentic research platform can improve the structure, reproducibility, and comparability of quantitative experiments. The platform therefore emphasizes modularity, experiment memory, standardized metrics, out-of-sample validation, and tool-mediated agent workflows. In this sense, the system is closer to a research operating system for quantitative experiments than to an autonomous trading bot.

本项目的核心研究问题并不是 LLM 能否直接发现盈利策略，而是智能体化研究平台能否提升量化实验的结构化程度、可复现性和可比较性。因此，平台重点关注模块化、实验记忆、标准化指标、样本外验证，以及通过工具调用实现的智能体工作流。从这个角度看，Quant MAS 更接近一个面向量化实验的研究操作系统，而不是自主交易机器人。

## 2. System Architecture / 系统架构

Quant MAS adopts a layered architecture consisting of a Quant Engine Layer, a Tool Layer, an Agent Layer, and a Memory/RAG Layer. The Quant Engine Layer performs deterministic computations such as OHLCV validation, feature construction, model training, strategy signal generation, backtesting, walk-forward validation, and risk checks. The Tool Layer wraps these capabilities into auditable callable tools, while the Agent Layer routes user requests and coordinates tools without directly modifying portfolio positions. The Memory/RAG Layer records experiments, artifacts, documents, and retrieval contexts for future research.

Quant MAS 采用分层架构，包括 Quant Engine Layer、Tool Layer、Agent Layer 和 Memory/RAG Layer。Quant Engine Layer 负责 OHLCV 数据校验、特征构建、模型训练、策略信号生成、回测、walk-forward 验证和风控检查等确定性计算。Tool Layer 将这些能力封装为可审计的工具；Agent Layer 根据用户请求进行路由和工具编排，但不直接修改投资组合仓位；Memory/RAG Layer 则记录实验、产物、文档和检索上下文，为后续研究提供支持。

The current tool registry includes data summary, backtest, model training, report generation, risk checks, ML backtesting, and full pipeline execution. The SupervisorAgent uses rule-based routing rather than complex agent frameworks in the first implementation stage. This design choice keeps the system interpretable and testable, while still leaving room for optional LangGraph workflows, local vLLM integration, and enterprise memory backends in later phases.

当前工具注册表包含数据摘要、回测、模型训练、报告生成、风控检查、机器学习回测和端到端 pipeline 执行等工具。SupervisorAgent 在第一版中使用规则路由，而不是一开始引入复杂的智能体框架。这一设计选择保持了系统的可解释性和可测试性，同时也为后续可选的 LangGraph 工作流、本地 vLLM 接入和企业级记忆后端预留了扩展空间。

## 3. Data and Feature Pipeline / 数据与特征流程

The data layer supports multiple data sources, including yfinance, Stooq, Alpha Vantage, Finnhub, FRED, and SEC EDGAR, while tests avoid real network calls through synthetic data and mocked HTTP responses. Market data are standardized into the OHLCV schema `date, symbol, open, high, low, close, volume` and stored in Parquet format. The storage layer uses cross-platform `pathlib.Path` paths and YAML configuration to keep local and server environments consistent.

数据层支持多个数据源，包括 yfinance、Stooq、Alpha Vantage、Finnhub、FRED 和 SEC EDGAR，同时测试通过 synthetic data 和 mock HTTP 响应避免真实网络请求。市场数据统一为 `date, symbol, open, high, low, close, volume` 的 OHLCV 格式，并以 Parquet 存储。存储层使用跨平台的 `pathlib.Path` 路径和 YAML 配置，以保持本地与服务器环境的一致性。

The feature pipeline constructs technical indicators such as returns, moving averages, moving-average distance, volatility, volume features, and RSI. Labels are generated separately through future returns and future direction labels. To prevent future leakage, label columns and future-looking fields are excluded from model features and from strategy replay inputs. Rolling features are computed in chronological order and grouped by symbol, ensuring that multiple symbols do not contaminate one another.

特征流程构建了收益率、移动均线、均线距离、波动率、成交量特征和 RSI 等技术指标。标签通过未来收益和未来方向标签单独生成。为避免未来函数，标签列和未来信息列不得进入模型特征，也不得进入策略回放输入。滚动特征按时间顺序计算，并按标的分组，确保多标的数据不会相互污染。

## 4. Modeling and Strategy Families / 模型与策略族

The platform currently supports several strategy families. First, a moving-average crossover strategy provides a deterministic rule-based baseline. Second, a LightGBM direction model predicts future direction labels and feeds probabilities into an MLSignalStrategy. Third, a population-learning pipeline generates rule-based candidates such as momentum and mean-reversion variants, which are exported into a unified StrategyCandidate schema. Fourth, the RL pipeline trains simulation-only policy candidates and exports them into the same validation interface.

平台当前支持多个策略族。第一类是移动均线交叉策略，作为确定性的规则基线。第二类是 LightGBM 方向预测模型，用于预测未来方向标签，并将概率输入 MLSignalStrategy。第三类是种群学习流程，生成 momentum 和 mean-reversion 等规则型候选，并导出为统一的 StrategyCandidate 格式。第四类是强化学习流程，在仿真环境中训练策略候选，并将其导出到同一验证接口。

The unifying design is that strategy discovery and strategy validation are separated. Population learning, reinforcement learning, and ML training may produce candidates or candidate-selection metrics, but they cannot write paper-level `oos.*` metrics directly. Only the independent walk-forward validation hook is allowed to produce out-of-sample metrics. This prevents simulation scores, in-sample backtests, or agent-generated narratives from being mistaken for out-of-sample evidence.

统一的设计原则是将策略发现与策略验证分离。种群学习、强化学习和机器学习训练可以产生候选或候选选择指标，但不能直接写入论文级别的 `oos.*` 指标。只有独立的 walk-forward 验证钩子被允许产生样本外指标。这样可以避免将仿真分数、样本内回测或智能体生成的叙事误认为样本外证据。

## 5. Experiment Memory and Research Protocol / 实验记忆与研究规范

ExperimentMemory stores experiment records, metrics, configurations, artifacts, and notes in append-only JSON or alternative backends such as SQLite and Postgres. The memory system supports retrieval by experiment id, name search, metric sorting, artifact path listing, and comparison table generation. This makes experiment results traceable and reduces the risk of cherry-picking or mixing incompatible metrics.

ExperimentMemory 以 append-only JSON 或 SQLite、Postgres 等替代后端存储实验记录、指标、配置、产物和备注。记忆系统支持按实验 ID 查询、名称搜索、指标排序、产物路径列举和比较表生成。这使实验结果具有可追踪性，并降低了选择性报告或混合不可比指标的风险。

The research protocol explicitly states that paper-level conclusions must use walk-forward OOS metrics. In this project, EXP-20260602-008 is treated as the main ML walk-forward baseline with `oos.sharpe = 0.586`. Single-segment ML backtests, simulation Sharpe, population Elo, and LLM-generated explanations are auxiliary evidence only. They can motivate hypotheses or ablations, but they cannot replace OOS validation.

研究规范明确规定，论文级结论必须使用 walk-forward 样本外指标。在本项目中，EXP-20260602-008 被作为主要 ML walk-forward 基线，其 `oos.sharpe = 0.586`。单段 ML 回测、仿真 Sharpe、种群 Elo 和 LLM 生成的解释仅作为辅助证据。它们可以用于提出假设或支持消融分析，但不能替代样本外验证。

## 6. Experimental Results / 实验结果

The main ML walk-forward baseline, EXP-20260602-008, achieved `oos.sharpe = 0.586` and `oos.total_return = 0.443` over 19 walk-forward windows. This result is used as the primary benchmark because it comes from the dedicated out-of-sample validation pipeline. It is therefore more suitable for paper-level reporting than single-run backtests or simulation metrics.

主要 ML walk-forward 基线 EXP-20260602-008 在 19 个 walk-forward 窗口上取得了 `oos.sharpe = 0.586` 和 `oos.total_return = 0.443`。该结果来自专门的样本外验证流程，因此被作为主要 benchmark。相比单次回测或仿真指标，该结果更适合用于论文级报告。

The text-signal ablation EXP-TEXT-WF-001 integrated FinBERT-derived text signals into the feature table and reached `oos.sharpe = 0.563`, slightly below the ML baseline by approximately `-0.023`, under only 3.32% text coverage. EXP-TEXT-WF-002 repeated the same walk-forward protocol with 100% coverage using feature-aligned placeholder headlines and reached `oos.sharpe = 0.579`, narrowing the gap to `-0.007` but still below the main baseline. EXP-TEXT-WF-003 used real Finnhub company news aligned by publication timestamp. Fetch window: **2025-06-04 ~ 2026-06-04** (9434 records); 5088 aligned; 146 FinBERT signal rows; effective feature overlap **~2025-06-04 ~ 2025-12-31**; 2.42% coverage; `text_signal_fillna=0`; `oos.sharpe = 0.565`, similar to WF-001 and below both the main baseline and WF-002. These results suggest that sparse coverage and missing-value filling materially hurt the first text experiment, that full-coverage placeholder text can recover much of the wf001 gap without beating the baseline, and that real news at comparable sparse coverage does not yet demonstrate incremental alpha. All three runs should be reported as exploratory.

文本信号消融 EXP-TEXT-WF-001 在仅 3.32% 文本覆盖率下将 FinBERT 信号并入特征表，得到 `oos.sharpe = 0.563`，比 ML 主基线低约 `-0.023`。EXP-TEXT-WF-002 在相同 walk-forward 协议下将覆盖率提升至 100%（占位标题文本），得到 `oos.sharpe = 0.579`，与主基线差距收窄至 `-0.007`，但仍未超越主基线。EXP-TEXT-WF-003 使用按发布时间对齐的 Finnhub 真实公司新闻。Fetch 窗口 **2025-06-04 ~ 2026-06-04**（9434 条）；对齐 5088 条；146 条 FinBERT 信号行；与 features 有效重叠约 **2025-06-04 ~ 2025-12-31**；覆盖率 2.42%；`text_signal_fillna=0`；得到 `oos.sharpe = 0.565`，与 WF-001 接近，低于主基线与 WF-002。这表明 wf001 的部分劣势来自稀疏覆盖与缺失值填充，全量占位文本可恢复 wf001 的大部分差距但仍未超越主基线，而在相近稀疏覆盖下真实新闻尚未展示信息增量。三项结果均应报告为 exploratory。

The population-learning OOS results show strong rule-based candidate performance. EXP-POP-005 evaluated a single mean-reversion candidate and reached `oos.sharpe = 1.036`. EXP-POP-006 evaluated a batch of four mean-reversion candidates, all of which exceeded the ML baseline, with the best candidate reaching approximately `1.039`. These results demonstrate that the candidate-generation and walk-forward validation bridge is functional, while also showing that population ranking and OOS ranking may differ.

种群学习的 OOS 结果显示出较强的规则型候选表现。EXP-POP-005 对单个 mean-reversion 候选进行评估，得到 `oos.sharpe = 1.036`。EXP-POP-006 批量评估了四个 mean-reversion 候选，四个候选均超过 ML 主基线，其中最佳候选约为 `1.039`。这些结果说明候选生成与 walk-forward 验证桥接机制是有效的，同时也显示种群排名与 OOS 排名可能并不一致。

The RL ablation results provide a useful contrast. The initial logits-based RL export in EXP-POP-009 produced an all-cash candidate with `oos.sharpe = 0.0`. After introducing the observation-aware feature-linear policy in M12.4, EXP-POP-010 improved the exported RL candidate to `oos.sharpe = 0.387` and `oos.total_return = 0.338`. This confirms that the RL bridge can produce state-dependent market exposure, but the result remains below the ML baseline of `0.586`.

强化学习消融结果提供了有价值的对照。最初的 logits-based RL 导出在 EXP-POP-009 中产生了全现金候选，`oos.sharpe = 0.0`。在 M12.4 引入观测感知 feature-linear 策略后，EXP-POP-010 将导出的 RL 候选提升到 `oos.sharpe = 0.387`、`oos.total_return = 0.338`。这证明 RL 桥接机制能够产生状态相关的市场暴露，但该结果仍低于 `0.586` 的 ML 主基线。

## 7. Discussion / 讨论

The strongest current OOS result comes from the population-generated mean-reversion candidate family rather than from the ML or RL candidate families. This does not necessarily mean that population learning is universally superior, because the candidates are rule-based, the asset universe and feature scope are limited, and further robustness checks are needed. However, it does indicate that the StrategyCandidate bridge and independent OOS validation framework can reveal non-trivial candidate behavior.

当前最强的 OOS 结果来自种群生成的 mean-reversion 规则候选，而不是 ML 或 RL 候选。这并不必然意味着种群学习在一般意义上优于其他方法，因为这些候选是规则型的，资产池和特征范围有限，并且仍需要进一步稳健性检验。但该结果说明，StrategyCandidate 桥接机制和独立 OOS 验证框架能够揭示非平凡的候选策略行为。

The RL results should be interpreted conservatively. The transition from `0.0` to `0.387` is meaningful because it demonstrates that observation-aware policies can avoid the all-cash failure mode. Nevertheless, the current one-step smoke training remains insufficient as a competitive research signal. Future RL work should include longer training, multiple random seeds, alternative action spaces, and systematic OOS batch evaluation before making stronger claims.

强化学习结果应谨慎解释。从 `0.0` 提升到 `0.387` 是有意义的，因为它证明观测感知策略可以避免全现金失败模式。然而，当前的一步 smoke 训练仍不足以成为具有竞争力的研究信号。后续 RL 工作应包括更长训练、多随机种子、不同动作空间，以及系统性的 OOS 批量评估，然后才能提出更强结论。

The text-signal result also suggests that adding LLM- or NLP-derived signals is not automatically beneficial. The three FinBERT walk-forward experiments span 3.32% smoke coverage (`0.563`), 100% placeholder coverage (`0.579`), and 2.42% real Finnhub news coverage (`0.565`). None exceeded the ML baseline of `0.586`. A more convincing text-enhanced study should improve historical news coverage (Finnhub free tier is limited to about one year), evaluate multiple text aggregation windows, and compare results through the same walk-forward OOS protocol.

文本信号结果也表明，引入 LLM 或 NLP 衍生信号并不会自动提升策略表现。三项 FinBERT walk-forward 实验分别对应 3.32% smoke 覆盖（`0.563`）、100% 占位覆盖（`0.579`）和 2.42% Finnhub 真实新闻覆盖（`0.565`），均未超过 `0.586` 的 ML 主基线。更有说服力的文本增强研究应提高历史新闻覆盖率（Finnhub 免费版约仅 1 年）、评估多个文本聚合窗口，并通过同一 walk-forward OOS 协议进行比较。

## 8. Safety and Auditability / 安全性与可审计性

A key contribution of Quant MAS is its safety boundary: agents do not directly place live orders. All agent outputs are treated as research proposals, explanations, reports, or tool calls. The RiskTool, backtesting engine, walk-forward validation module, and ExperimentMemory provide a structured audit trail. This makes the system more appropriate for educational and research use than for autonomous execution.

Quant MAS 的一个关键贡献是其安全边界：智能体不直接进行实盘下单。所有智能体输出都被视为研究建议、解释、报告或工具调用。RiskTool、回测引擎、walk-forward 验证模块和 ExperimentMemory 提供了结构化审计链路。这使系统更适合教育和科研用途，而不是自主执行交易。

The system also enforces a distinction among metric families. Training metrics, simulation metrics, backtest smoke metrics, and out-of-sample metrics are recorded separately. For example, `simulation.sharpe_mean = 12.13` in the M12.4 RL run must not be compared directly with the ML OOS baseline `0.586`. This separation is essential for academic rigor.

系统还强制区分不同指标族。训练指标、仿真指标、回测 smoke 指标和样本外指标被分别记录。例如，M12.4 RL 运行中的 `simulation.sharpe_mean = 12.13` 不能直接与 ML OOS 主基线 `0.586` 比较。这种分离对学术严谨性至关重要。

## 9. Limitations / 局限性

The current study has several limitations. First, the reported OOS results are based on the current available feature table and asset universe, and broader asset coverage may change the conclusions. Second, the text experiment has limited text coverage and should be treated as exploratory. Third, the RL pipeline currently validates the bridge mechanism but has not yet demonstrated competitive OOS performance. Fourth, the population candidates need additional robustness tests, such as transaction-cost sensitivity, regime segmentation, and multi-universe validation.

当前研究存在若干局限。第一，报告的 OOS 结果基于当前可用特征表和资产范围，更广泛的资产覆盖可能改变结论。第二，文本实验的文本覆盖率有限，应视为探索性结果。第三，RL 流程目前验证了桥接机制，但尚未展示具有竞争力的 OOS 表现。第四，种群候选仍需要额外稳健性检验，例如交易成本敏感性、市场状态分段和多资产池验证。

Another limitation is that the MAS layer is currently used mainly for orchestration and explanation rather than autonomous scientific discovery. This is intentional for safety and reproducibility, but it also means that the platform's agentic capabilities should be evaluated by workflow quality, experiment traceability, and research productivity rather than by claiming that the agent itself discovers alpha.

另一个局限是，MAS 层当前主要用于编排和解释，而不是完全自主的科学发现。这是出于安全性和可复现性的有意设计，但也意味着平台的智能体能力应通过工作流质量、实验可追踪性和研究效率来评价，而不是声称智能体本身直接发现 alpha。

## 10. Future Work / 后续工作

EXP-TEXT-WF-003 has now been completed. Real Finnhub company news aligned by publication timestamp reached `oos.sharpe = 0.565` under 2.42% coverage, similar to WF-001 and below both the ML baseline (`0.586`) and the full-coverage placeholder run (`0.579`). This suggests that coverage and fillna handling matter, but real news at current sparse coverage does not yet beat deterministic technical features alone.

EXP-TEXT-WF-003 现已完成。按发布时间对齐的 Finnhub 真实公司新闻在 2.42% 覆盖率下得到 `oos.sharpe = 0.565`，与 WF-001 接近，低于 ML 主基线（`0.586`）和全量占位实验（`0.579`）。这表明覆盖率与 fillna 处理很重要，但在当前稀疏覆盖下，真实新闻尚未超越纯技术特征。

Recommended next directions include longer historical news via paid Finnhub or alternate sources, optional FinBERT LoRA fine-tuning (EXP-TEXT-002), and M13 orchestration to consolidate repeated research flows into auditable pipelines.

后续方向包括：通过付费 Finnhub 或其他来源获取更长历史新闻、可选 FinBERT LoRA 微调（EXP-TEXT-002），以及 M13 编排以将重复研究流程整合为可审计 pipeline。

RL can be continued as an optional ablation track. A more rigorous RL study should perform longer feature-linear training, multiple seeds, action-space ablations, and M11.8 batch OOS evaluation. The goal should be to determine whether RL candidates can consistently exceed the ML baseline, not merely whether simulation rewards are high.

RL 可以作为可选消融方向继续推进。更严谨的 RL 研究应包括更长的 feature-linear 训练、多随机种子、动作空间消融和 M11.8 批量 OOS 评估。目标应是判断 RL 候选能否稳定超过 ML 主基线，而不是仅仅观察仿真奖励是否较高。

## 11. Conclusion / 结论

Quant MAS demonstrates a practical architecture for combining multi-agent research workflows with deterministic quantitative engines. The project shows that agents can coordinate data, models, strategies, reports, memory, and validation without directly executing trades. The most important methodological contribution is the separation between candidate generation and independent walk-forward OOS validation.

Quant MAS 展示了一种将多智能体研究工作流与确定性量化引擎结合的实践架构。项目表明，智能体可以协调数据、模型、策略、报告、记忆和验证，而不需要直接执行交易。最重要的方法论贡献是将候选生成与独立 walk-forward 样本外验证分离。

Empirically, the current ML baseline achieves `oos.sharpe = 0.586`, text enhancement reaches `0.563` under sparse smoke coverage, `0.579` under full-coverage placeholder text, and `0.565` under real Finnhub news at 2.42% coverage, population-generated rule candidates reach approximately `1.036-1.039`, and observation-aware RL reaches `0.387` after improving over an all-cash RL ablation.

从实证结果看，当前 ML 主基线达到 `oos.sharpe = 0.586`，稀疏 smoke 覆盖文本增强为 `0.563`，全量占位文本为 `0.579`，Finnhub 真实新闻 2.42% 覆盖为 `0.565`，种群生成规则候选达到约 `1.036-1.039`，观测感知 RL 则在相较全现金 RL 消融提升后达到 `0.387`。

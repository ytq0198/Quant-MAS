# Contributing to Quant MAS

Thanks for your interest in Quant MAS. Contributions are welcome from students, researchers, and engineers who care about reproducible quantitative research and safe agent systems.

感谢你关注 Quant MAS。欢迎提交 Issue、实验报告、文档改进、测试补充和功能 PR。

---

## Development Setup

```bash
git clone https://github.com/ytq0198/Quant-MAS.git
cd Quant-MAS

python -m pip install -e .
python -m pytest -v
```

Optional extras:

```bash
python -m pip install -r requirements-data.txt
python -m pip install -r requirements-ml.txt
python -m pip install -e ".[orchestration]"
python -m pip install -e ".[text]"
```

Use `python -m pip` and `python -m pytest` so the active interpreter is explicit.

## Testing Rules

Before opening a PR, run:

```bash
python -m pytest -v
```

Tests must:

- use synthetic data, local fixtures, or mocks;
- not call real LLM APIs;
- not rely on real network requests;
- not download large model weights;
- not write large files into `data/`, `outputs/`, `models/`, or `logs/`.

---

## Code Style

- Keep changes small and focused.
- Prefer `pathlib.Path` for paths.
- Prefer YAML configs for experiment parameters.
- Keep deterministic computation in the Quant Engine.
- Keep LLM output separate from factual metrics and artifacts.
- Add tests when adding tools, agents, strategies, models, data fetchers, or feature transforms.

---

## Adding a Tool

1. Implement a class inheriting `BaseTool`.
2. Return `ToolResult`, not a full DataFrame.
3. Put summaries in `content` and paths/metrics in `metadata`.
4. Register it through `ToolRegistry`.
5. Add a test using `tmp_path` and synthetic data.

Suggested locations:

- `src/quant_mas/tools/quant/`
- `tests/test_quant_tools.py`

---

## Adding an Agent

1. Inherit from `BaseAgent` when using an LLM boundary.
2. Keep loops bounded with `max_steps`.
3. Use `MockLLMClient` in tests.
4. Do not route agents directly to broker/order APIs.
5. Clearly separate facts from LLM interpretation.

Suggested locations:

- `src/quant_mas/agents/`
- `tests/test_agent_core.py`

---

## Adding a Strategy

1. Generate deterministic signals such as `target_weight`.
2. Do not place orders inside a strategy.
3. Let `BacktestEngine` handle execution timing.
4. Respect next-bar execution assumptions.
5. Add focused tests for signal generation and backtest behavior.

Suggested locations:

- `src/quant_mas/strategies/`
- `tests/test_backtest.py`

---

## Adding a DataFetcher

1. Keep API keys in environment variables only.
2. Do not log API keys.
3. Normalize OHLCV data to:
   `date, symbol, open, high, low, close, volume`
4. Run `validate_ohlcv()` for OHLCV sources.
5. Mock HTTP in tests.

Suggested locations:

- `src/quant_mas/data/fetchers/`
- `tests/test_data_sources.py`

## Issues

When opening an issue, include:

- environment and Python version;
- command used;
- config path;
- data source;
- whether LLM/Agent features were enabled;
- expected vs actual behavior;
- acceptance criteria.

Use the templates under `.github/ISSUE_TEMPLATE/`.

---

## Pull Requests

Good PRs usually include:

- a clear motivation;
- a small implementation scope;
- tests;
- updated docs or configs when needed;
- no secrets, no large generated artifacts.

PR checklist:

- [ ] `python -m pytest -v` passes
- [ ] No real API keys or secrets committed
- [ ] No large datasets or model weights committed
- [ ] LLM Agent does not directly place live orders
- [ ] Metrics remain generated by Quant Engine, not invented by LLM output

---

## Safety Requirements

Quant MAS is a research system.

- LLM Agents must not directly place live orders.
- LLM Agents must not output broker instructions as executable actions.
- All trading signals must pass backtesting, risk checks, audit, and human confirmation.
- Never commit `.env`, API keys, private SSH keys, large datasets, model checkpoints, or private logs.

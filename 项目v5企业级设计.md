# Quant MAS v5 Enterprise Research Platform Design / 企业级研究平台设计

> 目标：在 Quant MAS v4 Phase 1-4 已完成的全栈骨架基础上，结合现有代码和可用服务器条件，设计一条更企业级、但仍可落地的 v5 路线。

---

## 1. 设计结论 / Design Conclusion

ChatGPT 给出的 v5 Enterprise Architecture 方向是正确的，但对当前项目来说不应立刻走完整微服务、OAuth2、Kubernetes、复杂观测平台和多环境发布。

更适合 Quant MAS 当前阶段的路线是：

```text
v5.0: Server-first Enterprise Monolith
v5.1: Real ExperimentMemory + Artifact Integration
v5.2: Postgres / pgvector / Neo4j Optional Integration
v5.3: Auth / RBAC / Audit Hardening
v5.4: Human Review + Job Queue
v5.5: Observability + Deployment Polish
```

中文总结：

当前最优路线不是“马上拆微服务”，而是先做一个服务器可运行的企业级单体系统。后端仍保持 FastAPI monolith，前端仍保持 React/Vite，数据库和 RAG 逐步接入。等系统稳定后，再考虑拆 Agent Service、Experiment Service、Audit Service 等服务。

## 3. 服务器条件带来的变化 / What the Server Changes

你有服务器可用，因此 v5 不应该只停留在本地 demo。

服务器可以承担：

| Capability | English | 中文 |
|---|---|---|
| Persistent API | Run FastAPI continuously with Uvicorn/Gunicorn. | 持续运行 FastAPI 服务。 |
| Frontend hosting | Serve built frontend with Nginx/Caddy. | 用 Nginx/Caddy 托管前端 build 产物。 |
| Database | Run Postgres and optional pgvector. | 运行 Postgres 和可选 pgvector。 |
| Graph DB | Run optional Neo4j for graph relationships. | 运行可选 Neo4j 关系图谱。 |
| RAG indexing | Build document and experiment vector indexes. | 构建文档与实验向量索引。 |
| Long jobs | Run backtests, OOS, artifact export, and RAG indexing jobs. | 运行回测、OOS、论文导出、RAG 索引等长任务。 |
| Remote demo | Provide a stable URL for project review or internship showcase. | 提供稳定访问地址，用于展示和交流。 |

因此 v5 的重点应调整为：

1. 先把 v4 服务器化。
2. 再把 mock API 接到真实 `src/quant_mas/` artifacts。
3. 再接 Postgres / pgvector / Neo4j。
4. 最后再做 Auth / RBAC / Human Review / Observability。

### 4.2 Why not immediate microservices? / 为什么不立刻微服务化？

English:
The current project is still evolving quickly. Splitting services too early would increase configuration, deployment, testing, and debugging cost without improving research quality.

中文：
当前项目仍在快速演进。过早拆成微服务会显著增加配置、部署、测试和调试成本，但并不会直接提升研究质量。

Recommended rule:

```text
Keep monolith until one module has:
1. independent state,
2. independent scaling needs,
3. independent failure mode,
4. stable API contract.
```

建议规则：

只有当某个模块具备独立状态、独立扩展需求、独立故障模式和稳定 API 合约时，再考虑拆服务。

## 5. v5 Service Boundaries / v5 服务边界

### Keep in monolith first / 先保留在单体内

| Module | Reason |
|---|---|
| Backend API | Current FastAPI structure is small and clear. |
| Quant Engine Adapter | Needs close access to existing `src/quant_mas/`. |
| Agent / Tool API | Still mock-safe and evolving. |
| Backtest / OOS / Risk API | Should first read real artifacts before service split. |
| Memory/RAG API | Needs integration with existing memory and RAG modules first. |
| Artifact Export API | Already tied to existing paper artifact scripts. |

中文说明：

这些模块目前应留在 FastAPI 单体中，因为它们仍在和现有 `src/quant_mas/` 核心模块磨合。先接真实数据和 artifacts，比拆服务更重要。

### Future service candidates / 未来可拆服务

| Service | Split when |
|---|---|
| Experiment Service | Experiment registry and metrics become stable and database-backed. |
| Agent Service | Agent runs become long-running and need queue/streaming. |
| RAG Service | pgvector/Neo4j indexing becomes heavy or independent. |
| Audit Service | Audit logs need append-only storage and separate access policy. |
| Artifact Service | Paper exports become frequent and need background jobs. |

### 6.2 Development vs server / 本地与服务器分工

| Task | Local machine | Server |
|---|---|---|
| UI development | Yes | No |
| Fast iteration | Yes | No |
| Long experiment jobs | Optional | Yes |
| Persistent API | Optional | Yes |
| Team/demo access | No | Yes |
| Database/RAG indexing | Optional | Yes |

结论：

本地用于前端和代码快速迭代；服务器用于稳定运行后端、数据库、RAG 索引、长任务和项目展示。

## 8. Database Schema Priority / 数据库 schema 优先级

ChatGPT 给出的 schema 很完整，但 v5 不应一次性全部实现。

### Phase 5 first tables / Phase 5 优先表

```text
experiments
experiment_metrics
backtest_runs
oos_runs
risk_reviews
audit_logs
paper_artifacts
```

原因：

这些表直接服务于已有 API 和科研展示，优先级最高。

### Phase 6 auth tables / Phase 6 认证表

```text
users
roles
api_keys
sessions
```

原因：

只有当服务器开放给他人访问时，认证和权限才变成必须项。

### Phase 7 RAG tables / Phase 7 RAG 表

```text
memory_items
rag_documents
document_chunks
embedding_jobs
```

原因：

RAG 接入需要先明确文档来源、chunk 策略和向量模型。

### Neo4j graph / Neo4j 图谱

Neo4j 暂时不要作为必需依赖。建议先作为演示增强：

```text
Experiment -> uses -> Tool
Agent -> calls -> Tool
Experiment -> produces -> Artifact
Document -> supports -> Experiment
Candidate -> evaluated_by -> OOSRun
```

## 10. Security and Safety / 安全设计

v5 必须继续保留以下原则：

1. LLM agents do not place live orders.
2. No broker/order endpoint is exposed.
3. ToolPolicy rejects shell, broker, order, and secrets access.
4. All candidate decisions require backtest, risk check, audit log, and human confirmation.
5. `oos.*` is separated from `simulation.*`, `training.*`, `population.*`, and `audit.*`.
6. UI must show research-only disclaimer.
7. Server `.env` must never be committed.

服务器额外要求：

| Area | Recommendation |
|---|---|
| Secrets | Use `.env` on server, never commit API keys. |
| Network | Keep DB ports private if possible. |
| Auth | Start with simple login/JWT before public sharing. |
| Logs | Store append-only audit logs. |
| Backup | Back up DB, outputs, and artifacts. |

## 12. Recommended Migration Plan / 推荐迁移路线

### Phase 5: Real ExperimentMemory and artifact integration

English:
Connect current fixture APIs to real `outputs/`, `docs/experiment_log.md`, `ExperimentMemory`, and paper artifacts.

中文：
把当前 fixture API 接到真实 `outputs/`、`docs/experiment_log.md`、`ExperimentMemory` 和论文产物。

Acceptance criteria:

- `/api/experiments` returns real experiment records or parsed local artifacts.
- `/api/oos/EXP-20260602-008` reads from real registry/artifact source where possible.
- `/api/artifacts/paper` lists exported paper files.
- Tests still do not require network or real LLM.

### Phase 6: Server deployment hardening

English:
Make the server deployment repeatable with `.env.example`, service scripts, and deployment docs.

中文：
通过 `.env.example`、服务脚本和部署文档，让服务器部署可重复。

Acceptance criteria:

- Server can run backend persistently.
- Frontend build can be served by Nginx/Caddy or container.
- Logs and outputs are stored outside the repo working tree.
- No secrets are committed.

### Phase 7: Postgres / pgvector integration

English:
Move experiment registry and memory search from fixture/local files to optional Postgres and pgvector.

中文：
将实验注册和记忆检索从 fixture/本地文件逐步迁移到可选 Postgres 和 pgvector。

Acceptance criteria:

- Local file mode still works.
- Postgres mode can list experiments.
- pgvector mode can run simple document retrieval.
- Tests can use fixtures or SQLite fallback.

### Phase 8: Human Review workflow

English:
Add a review queue for research candidates and paper-grade claims.

中文：
为研究候选和论文级结论增加人工审查队列。

Acceptance criteria:

- Review items can be created from risk/OOS outputs.
- Review decisions are written to audit logs.
- UI shows pending/approved/rejected states.

### Phase 9: Auth / RBAC / audit hardening

English:
Add login, roles, API keys, and stricter audit policy.

中文：
增加登录、角色、API key 和更严格的审计策略。

Acceptance criteria:

- Admin, Researcher, Reviewer roles exist.
- Sensitive endpoints require permission.
- Audit logs are append-only.

### Phase 10: Enterprise polish

English:
Polish UI, docs, demo workflow, deployment scripts, and release checklist.

中文：
完善 UI、文档、演示流程、部署脚本和发布清单。

Acceptance criteria:

- README explains v5 enterprise path.
- Demo can run on server.
- Docs explain local vs server workflows.
- No unsupported live-trading claims.

## 13. What to avoid / 当前不要做什么

不要现在就做：

- Full Kubernetes deployment.
- Complex OAuth provider integration.
- Hard dependency on Neo4j.
- Hard dependency on pgvector for all tests.
- Real broker integration.
- Live trading endpoint.
- Overly large microservice split.
- Claims about financial performance beyond audited OOS baseline.

原因：

这些会增加复杂度，但不会立刻提升项目展示、实习价值或论文可复现性。

## 15. Phase 5 Implementation Status / Phase 5 实施状态

当前已开始落地 Phase 5，采用 `server backend first` 设计。

已实现：

```text
GET /api/experiments

GET /api/artifacts/paper

```

数据源优先级：

```text
1. QUANT_MAS_EXPERIMENT_MEMORY_PATH / QUANT_MAS_PAPER_DIR / QUANT_MAS_AUDIT_DIR
2. QUANT_MAS_ARTIFACT_ROOT 下的 outputs/reports、outputs/paper、outputs/pipelines
3. fallback_baseline / fallback_empty
```

服务器部署建议：

```bash
export QUANT_MAS_ARTIFACT_ROOT=/path/to/Quant-MAS
export QUANT_MAS_EXPERIMENT_MEMORY_PATH=/path/to/outputs/reports/experiments.json
export QUANT_MAS_PAPER_DIR=/path/to/outputs/paper
export QUANT_MAS_AUDIT_DIR=/path/to/outputs/pipelines
python -m uvicorn backend.app:app --host 0.0.0.0 --port 8000
```

本机开发说明：

- 本机不要求存在服务器真实数据。
- 若 artifact 文件缺失或格式无效，API 不应崩溃。
- API 会返回 `fallback_baseline` 或 `fallback_empty`。
- 服务器真实 artifacts 对齐和 smoke test 交给 Cursor / 服务器侧验证。

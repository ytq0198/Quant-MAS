## 2. 后续总路线 / Remaining Roadmap

后续不再拆成很多单独设计文档，而按以下阶段连续推进：

```text
Phase 6: Auth / RBAC / Audit Hardening
Phase 7: Human Review + Job Queue Skeleton
Phase 8: RAG / Postgres / pgvector Optional Integration
Phase 9: Observability + Server Deployment Hardening
Phase 10: Enterprise Polish + Demo + Documentation
```

推荐实现原则：

1. 先 server-first monolith，不立刻微服务化。
2. 本机测试不依赖真实服务器数据。
3. 服务器真实数据、Docker、前端 build、浏览器截图交给 Cursor / 服务器验证。
4. 所有新增接口都要 fallback-safe。
5. 每次代码推进都跑目标 pytest 和 `compileall src/backend`。

## 4. Phase 6: Auth / RBAC / Audit Hardening

### Goal / 目标

Add lightweight enterprise access control for server mode without complex OAuth.

增加适合服务器模式的轻量企业级访问控制，不引入复杂 OAuth。

### Scope / 范围

新增：

```text
src/backend/security/
|-- roles.py
|-- api_keys.py
|-- dependencies.py
`-- audit.py
```

新增/更新：

```text
GET  /api/auth/me
POST /api/auth/validate-key
```

保护：

```text
POST /api/agents/run       # researcher+
GET  /api/audit/logs       # reviewer+ or admin
future POST tool endpoints # researcher+
```

### Auth mode / 认证模式

```text
QUANT_MAS_AUTH_MODE=open      # local default
QUANT_MAS_AUTH_MODE=api_key   # server recommendation
```

API key header:

```text
X-Quant-MAS-Key: <api-key>
```

Role config:

```text
QUANT_MAS_API_KEYS=viewer_key:viewer,researcher_key:researcher,reviewer_key:reviewer,admin_key:admin
```

### Roles / 角色

| Role | Level | Purpose |
|---|---:|---|
| viewer | 10 | Read experiments, artifacts, status. |
| researcher | 20 | Run controlled agents/tools. |
| reviewer | 30 | Read audit logs and review queue. |
| admin | 40 | Admin-level future settings. |

### Audit writer / 审计写入

Append-only JSONL:

```text
QUANT_MAS_AUDIT_WRITE_PATH=logs/backend_audit.jsonl
```

Must not write raw API keys.

不得写入明文 API key。

### Codex tests / Codex 目标测试

- open mode allows local access.
- api_key mode rejects missing key.
- viewer cannot call researcher route.
- researcher can call `/api/agents/run`.
- reviewer/admin can read audit logs.
- audit writer appends JSONL.
- raw API key is not written.

### Cursor / server tests

- Server can run with `QUANT_MAS_AUTH_MODE=api_key`.
- Frontend can store key and attach header.
- Audit JSONL writes to server log path.
- Nginx/Caddy does not expose `.env`, `logs`, or private `outputs`.

## 5. Phase 7: Human Review + Job Queue Skeleton

### Goal / 目标

Create a review queue and lightweight job status model before adding heavy async infrastructure.

在引入复杂异步系统前，先建立人工审查队列和轻量任务状态模型。

### New APIs / 新接口

```text
GET  /api/review/queue
GET  /api/review/{review_id}
POST /api/review/{review_id}/approve
POST /api/review/{review_id}/reject

GET  /api/jobs
GET  /api/jobs/{job_id}
GET  /api/jobs/{job_id}/events
```

### Review item model / 审查项模型

```json
{
  "review_id": "review-demo-001",
  "experiment_id": "EXP-20260602-008",
  "candidate_type": "paper_claim",
  "status": "pending",
  "required_gates": ["backtest", "risk_check", "audit_log", "human_confirmation"],
  "metric_family": "oos",
  "decision": null,
  "created_at": "..."
}
```

### Job model / 任务模型

```json
{
  "job_id": "job-demo-001",
  "type": "artifact_export",
  "status": "queued|running|completed|failed",
  "progress": 0.0,
  "events": []
}
```

### Implementation style / 实现方式

Phase 7 先使用 local JSONL / in-memory fixture，不立刻引入 Celery/Redis。

```text
outputs/review/review_queue.json
outputs/jobs/jobs.json
logs/jobs.jsonl
```

### Codex tests

- list review queue fallback works.
- approve/reject writes audit event.
- review decision requires reviewer/admin in api_key mode.
- jobs endpoint returns fallback job list.
- no live trading status is created.

### Cursor / server tests

- Server review queue reads configured artifact path.
- Frontend shows pending/approved/rejected.
- Audit logs include review decisions.

## 6. Phase 8: RAG / Postgres / pgvector Optional Integration

### Goal / 目标

Add optional database-backed experiment and RAG access without breaking local file mode.

增加可选数据库驱动的实验和 RAG 访问，同时不破坏本地文件模式。

### Priority / 优先级

不要一口气把 Postgres、pgvector、Neo4j 全做深。推荐顺序：

```text
8.1 SQLite/local fallback schema
8.2 Postgres experiment registry read path
8.3 pgvector document retrieval path
8.4 Neo4j graph status / relationships fixture
```

### New APIs / 新接口

```text
GET  /api/database/tables
GET  /api/rag/documents
POST /api/rag/index
GET  /api/rag/query?q=...
GET  /api/graph/relationships
```

### Config / 配置

```text
QUANT_MAS_STORAGE_MODE=local_files|sqlite|postgres
POSTGRES_DSN=
VECTOR_STORE=in_memory|pgvector
PGVECTOR_DSN=
NEO4J_URI=
NEO4J_USER=
NEO4J_PASSWORD=
```

### Data source rule / 数据源规则

```text
local_files remains default.
postgres/pgvector are optional server enhancements.
tests must pass without real DB.
```

### Codex tests

- local mode works without DB.
- invalid Postgres config returns status warning, not crash.
- RAG query returns fallback documents if no vector store.
- metric separation is preserved.

### Cursor / server tests

- Postgres connection smoke.
- pgvector extension availability.
- simple RAG query from indexed docs.
- optional Neo4j status smoke if installed.

## 10. Global Safety Rules / 全局安全规则

所有后续阶段必须遵守：

- Do not add live trading endpoints.
- Do not add broker/order capabilities.
- Do not expose secrets.
- Do not log raw API keys.
- Do not present simulation/backtest as OOS.
- Do not create unsupported performance claims.
- Do not turn fallback fixtures into fake experiment results.
- Do keep `LLM agents do not place live orders` visible in docs and UI.
